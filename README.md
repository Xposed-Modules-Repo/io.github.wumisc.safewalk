# 安全出行 SafeWalk

> 海阔天空，勇敢去走。

纯本地、无服务器的**出行感知** LSPosed 模块。不依赖 GMS，不联网，不上传任何数据；
用手机自带的计步器与加速度计判断你「是不是真的在走路」，再决定要不要提醒你。

- 运行环境：**HyperOS / Android 12+（minSdk 30，targetSdk 35）**
- 作用域：**只需勾选「系统界面」**，不需要系统框架
- 开源协议：**AGPL-3.0**（见 [LICENSE](LICENSE)）
- 当前版本：**2.9.2**

## ✨ 它能做什么

| 功能 | 触发条件 | 说明 |
|---|---|---|
| 🔋 电量预警 | 电量 ≤ 15% 且正在步行 | 提醒尽快充电，1 小时冷却 |
| 🪪 证件提醒 | 确认持续步行后 | 提醒证件贴身放好，每日 1 次 |
| 🪑 久坐提醒 | 停止走动满 2 小时 | 提醒起身活动，每日 1 次 |
| 🔦 夜间提醒 | 22:00~06:00 且正在步行 | 通知直接带「手电筒」按钮，点了就亮 |
| 🤝 社交礼仪 | 确认持续步行后 | 按出行模式（求职/约会/聚会/旅游）给 3 条提示 |
| 🚶 行走模式 | 开始步行（或常开） | 后置摄像头把身后路况叠在屏幕上 |
| 🚑 车祸预警 | 检测到剧烈撞击 | 全屏急救卡 + 60 秒倒计时，无响应自动求助 |

所有功能共用**同一个总开关**。总开关关闭时，二级菜单里的开关仍会保留设置，但不会生效——
界面上会明确写出「总开关未开（已设 5/5）」，而不是把真实状态藏起来。

## 🧠 步态检测：怎么避免「床上翻身也弹提醒」

只在「确实在走路」时才提醒，靠**五重判定**层层收敛：

1. **步数门槛**：5 分钟滑动窗口内累计 ≥ **50 步**（可调 20~200）才进入验证
2. **步态验证**：加速度计采样 **4 秒**，要求至少 **2 个步间隔**稳定在均值 **±250ms**、步频 **0.9~2.5Hz**（覆盖慢走到快跑；3Hz 以上抖腿仍然拒绝）
3. **平躺加权**：重力 Z 轴 > 8.5（手机平放）时峰值阈值 **×1.45**，翻身更难触发
4. **静置重置**：**20 秒**没有新步数（可调 5~60）直接回待机，什么都不弹
5. **冷却机制**：触发后 5 分钟内不重复；证件/久坐每日 1 次；电量 1 小时

> 峰值判定用自适应阈值：取最近 60 个样本的 `均值 + 1.8×标准差`，钳制在 0.6~2.8 m/s²。

```
SLEEP（待机）
  ↓ 计步器事件
LIGHT_MONITOR（5 分钟窗口计步）
  ↓ 累计 ≥ 阈值
VERIFYING（加速度计采样 4 秒，6 秒超时兜底）
  ↓ 判定为真步行
触发提醒（证件 → 社交 → 夜间手电）→ 回到 SLEEP
```

### 计步来源与兜底

系统计步器（`TYPE_STEP_DETECTOR`）与**加速度计计步恒定并行**，按 300ms 去重。

为什么不再「优先系统计步器、失败才兜底」：模块挂在 **SystemUI 进程**，
而 `TYPE_STEP_DETECTOR` 需要 `ACTIVITY_RECOGNITION` 运行时权限。
拿不到时注册**不会报错**，只是永远没有回调——表现和「没在走路」一模一样。
等 5 分钟再切兜底，用户早就放弃了。所以现在两条腿同时走：

- 加速度计每帧过一遍 `GaitDetector`（α=0.96 低通分离重力 → 主轴自适应 → 包络阈值计峰）
- 系统计步器若真能出数，事件同样计入，300ms 内重复的丢弃
- 3Hz 以上的抖腿 / 摇手机被步频窗口挡掉

注册失败、启动失败都会写日志，不会再出现「一步都没收到、日志里一个字没有」的情况。

## 📷 行走模式：相机在 App 进程，不在系统进程

这是 2.7 之后最重要的架构调整：

```
SystemUI 进程（LSPosed Hook）        App 进程
  ├─ 读传感器、判步态                  ├─ WalkPreviewService（前台服务，持相机）
  ├─ 读配置（Provider + 60s 缓存）      ├─ RearCameraOverlay（悬浮窗 + TextureView）
  └─ 只发「该显示 / 该收起」广播  ────→  └─ 真正 openCamera / 渲染
```

早期版本在 `com.android.systemui` 里直接开相机，会遇到三个绕不过去的问题：
系统界面没有相机权限、CameraService 对 systemui 的调用有额外限制、以及一崩溃就带走整个状态栏。
现在 Hook 只做「指挥」，相机全部回到 App 自己的前台服务里，失败最多是预览不出，不会影响系统界面。

**两种形态**

- **全屏叠加**：整屏按设定透明度显示后方画面，触摸完全穿透，下层应用照常使用
- **角落小窗**：150×260dp，可停靠四角

**关键参数**

| 项 | 配置键 | 范围 |
|---|---|---|
| 行走模式总开关 | enableRearCamera | — |
| 自动检测步行 | rearCamAuto | 走起来自动开、停下 20 秒自动收 |
| 显示形态 | rearCamMode | 全屏 / 小窗 |
| 小窗位置 | rearCamCorner | 四角 |
| 画面透明度 | rearCamOpacity | 10%~100% |
| 触发步数 | stepThreshold | 20~200 步 |
| 静置判定 | staticResetSec | 5~60 秒 |

其他特性：

- **实时预览**：改形态 / 位置 / 透明度会立刻拉一次预览，当场看到效果
- **相机避让**：前台是相机类应用时自动收起，离开后恢复
- **状态回执**：预览服务把「现在到底显示着没有」回传给 Hook，避免 Hook 端的去重状态和实际情况脱节（否则手动关掉一次，就再也自动开不出来）

## 🔦 手电筒

- **夜间提醒带按钮**：通知上的「手电筒」点了直接开灯，走 `CameraManager.setTorchMode()`，不需要相机权限、也不用握着相机
- **全局状态同步**：`TorchCallback` 监听真实闪光灯状态，控制中心开关手电也能同步
- **静置省电**：手电开着且静置超过设定分钟（5~60），提醒关灯省电
- **夜间提醒门槛**：22:00~06:00 + 屏幕亮着 + 正在步行 + 预览没占着相机，才弹

## 🚑 车祸预警（Pixel 风格）

- **检测**：SystemUI 进程持续监听加速度，合加速度超过阈值且**连续 2 次命中**才判定为撞击，60 秒冷却防连环误报
- **三档灵敏度**：低 ≈2.5g / 中 ≈2.0g（默认）/ 高 ≈1.5g
- **响应**：拉起全屏急救卡，**60 秒倒计时**
- **超时未点「我没事」**：先发含位置的求助短信，再拨紧急联系人（短信先发，避免拨号界面挡住）
- **降级**：没有短信/通话权限时，改为跳转短信应用预填内容、跳转拨号盘，不静默失败

需要 `CALL_PHONE`、`SEND_SMS`、定位权限，都在急救卡页面按需申请，不申请也不影响其他功能。

## 🔔 通知

所有提醒统一发**高优先级通知**（`IMPORTANCE_HIGH` + `PRIORITY_HIGH` heads-up），
可被 HyperOS 超级岛在 SystemUI 侧拦截，以焦点通知样式展示。

冷却**按通道独立计时**（电量/证件/久坐/社交/手电各自 60 秒），一次出门可能同时收到多条不同提醒。

## 🗂 日志

排查问题用，默认路径：

```
/storage/emulated/0/Android/Travel safely/diag.log
```

写入策略（逐级降级，不再出现「日志文件根本不存在」）：

1. 首选上述用户可见目录 —— 需要授予「所有文件访问」（Android 11+ 分区存储限制），
   首次打开 App 会引导授权，**授权后运行期直接热切换**，不用重启
2. 写不进则退到 `Android/data/io.github.wumisc.safewalk/files/logs/diag.log`
3. 都失败则只走 logcat

```bash
adb logcat -s SafeWalk
```

App 启动时会向 SystemUI 进程的 Hook 索要内存里的日志，写进**同一个文件**——
步态判定、手电、车祸检测都跑在那边，只看 App 侧等于没看。

实验区「当前日志目录」会显示实际落地路径，以及每个候选目录的探针结果。

## 🚀 安装

1. 在 LSPosed 中启用「安全出行」
2. **作用域只勾「系统界面（SystemUI）」**，不要勾系统框架
3. 重启系统界面（或重启手机）
4. 打开 App，授予「身体活动」权限（Android 13+ 另有通知权限）
5. 打开首页总开关，再按需进二级菜单配置

> 开关改完立即生效（写配置后主动广播）；预览是广播快通道，点下去就出画面。

## ⚠️ 已知限制

| # | 问题 | 影响 | 状态 |
|---|---|---|---|
| 1 | 依赖硬件计步器 `TYPE_STEP_DETECTOR` | 无此传感器的设备不会触发任何提醒 | 硬件限制 |
| 2 | 全屏叠加在个别 ROM 上不出画面 | 已限定为透明窗口路径（alpha 上限 0.99），仍可能被厂商悬浮窗策略拦截 | 待真机反馈 |
| 3 | 车祸检测靠加速度阈值 | 手机脱落摔地可能误报，故留了 60 秒倒计时可取消 | 设计取舍 |
| 4 | 配置 Provider 白名单基于包名 | 白名单包名被冒充时仍可读开关（不含隐私字段） | 残余风险可接受 |
| 5 | 实验区入口是长按「关于」页按钮 | 新用户找不到 | 刻意保留 |
